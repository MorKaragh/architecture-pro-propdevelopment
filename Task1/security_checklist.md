# Проверочный лист по безопасности данных PropDevelopment

## 1. Классификация данных по стандартам ISO/IEC 27001 и 27002

### 1.1. Публичные данные

**Описание:** Данные, которые могут быть открыто опубликованы без ущерба для компании и клиентов.

**Примеры данных:**
- Общая информация о жилых комплексах (название, адрес, количество квартир)
- Публичные характеристики объектов недвижимости (площадь, количество комнат, этаж)
- Общая информация о компании (контакты, история)
- Публичные отчёты и статистика (без персональных данных)
- Информация о планируемых работах по ремонту (без привязки к конкретным собственникам)

**Хранение и обработка:**
- Витрина продаж (showcase_sales)
- client-mart-estate-app
- client-mart-estate-db

### 1.2. Внутренние данные

**Описание:** Данные для внутреннего использования компании, не содержащие персональных данных клиентов, но требующие ограничения доступа.

**Примеры данных:**
- Внутренние бизнес-процессы и процедуры
- Метрики производительности систем
- Конфигурации систем и инфраструктуры
- Внутренние отчёты и аналитика (агрегированные данные без ПДн)
- Логи систем (без персональных данных)
- Информация о партнёрских интеграциях (технические детали)

**Хранение и обработка:**
- Хранилище данных (data_warehouse)
- Системы бухгалтерского учёта (accountant-service-1)
- Active Directory
- Логи и мониторинг систем

### 1.3. Конфиденциальные данные

**Описание:** Персональные данные клиентов и собственников, а также коммерчески чувствительная информация, требующая защиты согласно законодательству РФ.

**Примеры данных:**
- Персональные данные клиентов (ФИО, телефон, email, паспортные данные)
- Персональные данные собственников
- Финансовая информация (платёжные данные, история транзакций)
- Данные о сделках (бронирования, покупки недвижимости)
- Данные о платежах за ЖКУ
- История взаимодействий с клиентами
- Результаты осмотров объектов недвижимости
- Данные для онлайн-сделок
- Учётные данные пользователей (логины, хеши паролей)
- Данные о жилых комплексах и объектах недвижимости (детальная информация)

**Хранение и обработка:**
- client-crm-app, crm-db
- client-mart-app, client-mart-db
- client-tour-app, client-tour-db
- tenant-core-app, tenant-core-db
- crm (для собственников), crm-tenant-db
- auth-service-buyer, auth-db-buyer
- accountant-service-1, auth-db-2
- Хранилище данных (data_warehouse) — агрегированные и сырые данные

### 1.4. Секретные данные

**Описание:** Данные, утечка которых может привести к серьёзным правовым, финансовым или репутационным последствиям.

**Примеры данных:**
- Криптографические ключи и сертификаты
- Учётные данные администраторов систем
- Данные интеграций с государственными регистрационными органами (СМЭВ)
- Конфигурации безопасности (правила firewall, политики доступа)
- Данные аудита безопасности
- Коммерческая тайна (стратегия развития, финансовые показатели)
- Данные о партнёрских API (ключи доступа, токены)

**Хранение и обработка:**
- Active Directory (учётные данные)
- Системы аутентификации (ключи, токены)
- Конфигурации безопасности
- Интеграционные компоненты (СМЭВ, партнёрские API)

## 2. Риски для каждой категории данных

### 2.1. Публичные данные

#### 2.1.1. Утечка данных
**Описание риска:** Несанкционированное распространение публичных данных может привести к искажению информации о компании или объектах недвижимости.

**Обоснование актуальности:** 
- Публичные данные используются в витрине продаж и доступны внешним пользователям
- Искажение публичной информации может нанести репутационный ущерб
- Конкуренты могут использовать данные для анализа бизнес-стратегии

**Оценка риска:** Незначительный

#### 2.1.2. Потеря данных
**Описание риска:** Потеря публичных данных о объектах недвижимости может привести к недоступности витрины продаж.

**Обоснование актуальности:**
- Витрина продаж критична для бизнес-процессов продажи недвижимости
- Потеря данных приведёт к простою системы и потере продаж
- Восстановление данных возможно из резервных копий, но требует времени

**Оценка риска:** Значительный

#### 2.1.3. Искажение данных
**Описание риска:** Некорректное отображение информации об объектах недвижимости может привести к ошибкам при бронировании и продаже.

**Обоснование актуальности:**
- Искажение данных о площади, цене или характеристиках объектов может привести к юридическим проблемам
- Клиенты могут предъявить претензии при несоответствии заявленных и фактических характеристик
- Проблема уже проявляется: клиенты видят данные других клиентов в личном кабинете

**Оценка риска:** Значительный

#### 2.1.4. Некачественные данные
**Описание риска:** Некорректные или устаревшие данные об объектах недвижимости снижают эффективность продаж.

**Обоснование актуальности:**
- Несколько точек регистрации данных без координации (как указано в проблемах)
- Отсутствие единой системы контроля качества данных
- Некачественные данные снижают конверсию продаж

**Оценка риска:** Значительный

#### 2.1.5. Обесценивание данных
**Описание риска:** Публичные данные могут устареть и потерять актуальность.

**Обоснование актуальности:**
- Данные об объектах недвижимости должны обновляться в реальном времени
- Устаревшая информация о доступности объектов может привести к конфликтам с клиентами
- Риск относительно низкий, так как данные регулярно обновляются

**Оценка риска:** Незначительный

---

### 2.2. Внутренние данные

#### 2.2.1. Утечка данных
**Описание риска:** Утечка внутренних данных может раскрыть бизнес-процессы и техническую архитектуру компании конкурентам.

**Обоснование актуальности:**
- Внутренние данные содержат информацию о бизнес-процессах и метриках
- Утечка может помочь конкурентам понять стратегию развития
- Технические детали интеграций могут быть использованы для атак

**Оценка риска:** Значительный

#### 2.2.2. Потеря данных
**Описание риска:** Потеря внутренних данных (логов, метрик, конфигураций) может затруднить диагностику проблем и восстановление систем.

**Обоснование актуальности:**
- Логи и метрики критичны для мониторинга и диагностики инцидентов
- Потеря конфигураций может привести к длительному простою систем
- Восстановление возможно, но требует времени и ресурсов

**Оценка риска:** Значительный

#### 2.2.3. Искажение данных
**Описание риска:** Искажение внутренних данных (метрик, отчётов) может привести к принятию неверных управленческих решений.

**Обоснование актуальности:**
- Искажённые метрики могут привести к неправильной оценке эффективности бизнеса
- Некорректные отчёты влияют на стратегические решения
- Проблема актуальна, так как отсутствует системный контроль потоков данных

**Оценка риска:** Значительный

#### 2.2.4. Некачественные данные
**Описание риска:** Некачественные внутренние данные снижают эффективность бизнес-аналитики и принятия решений.

**Обоснование актуальности:**
- BI-аналитика зависит от качества данных в хранилище
- Некачественные данные блокируют развитие ML/AI-сервисов (как указано в проблемах)
- Отсутствие ограничений на доступ к данным в системах обработки может приводить к загрязнению данных

**Оценка риска:** Критический

#### 2.2.5. Обесценивание данных
**Описание риска:** Внутренние данные могут устареть и потерять актуальность для анализа.

**Обоснование актуальности:**
- Устаревшие метрики и отчёты теряют ценность для принятия решений
- Риск относительно низкий, так как данные регулярно обновляются через CDC

**Оценка риска:** Незначительный

---

### 2.3. Конфиденциальные данные

#### 2.3.1. Утечка данных
**Описание риска:** Утечка персональных данных клиентов и собственников может привести к серьёзным правовым последствиям, штрафам и репутационному ущербу.

**Обоснование актуальности:**
- Критически актуально: уже есть инциденты (клиенты видят данные других клиентов)
- Несколько точек регистрации клиентов без координации
- Проблемы с API партнёров: контракты позволяют получать данные, к которым не должно быть доступа
- Недавний инцидент у конкурента активно обсуждался в СМИ
- Нарушение требований законодательства РФ (152-ФЗ) может привести к крупным штрафам
- Утечка финансовых данных может привести к мошенничеству

**Оценка риска:** Критический

#### 2.3.2. Потеря данных
**Описание риска:** Потеря персональных данных и данных о сделках может привести к невозможности восстановления истории взаимодействий с клиентами и юридическим проблемам.

**Обоснование актуальности:**
- Потеря данных о сделках может привести к юридическим спорам
- Персональные данные требуются для соответствия законодательству
- Резервное копирование выполняется, но потеря данных может произойти до создания бэкапа
- Критично для восстановления после инцидентов

**Оценка риска:** Критический

#### 2.3.3. Искажение данных
**Описание риска:** Искажение персональных данных или данных о сделках может привести к ошибкам в работе с клиентами и юридическим проблемам.

**Обоснование актуальности:**
- Уже проявляется: клиенты видят данные других клиентов (как указано в проблемах)
- Искажение данных о сделках может привести к финансовым потерям
- Несколько точек регистрации без координации увеличивают риск искажения
- Искажение данных при интеграции с госорганами может привести к проблемам с регистрацией сделок

**Оценка риска:** Критический

#### 2.3.4. Некачественные данные
**Описание риска:** Некачественные персональные данные снижают эффективность работы с клиентами и могут привести к ошибкам в обработке.

**Обоснование актуальности:**
- Несколько точек регистрации клиентов без координации
- Некачественные данные затрудняют работу менеджеров и CRM-систем
- Могут привести к ошибкам при проведении онлайн-сделок
- Влияют на качество обслуживания клиентов

**Оценка риска:** Значительный

#### 2.3.5. Обесценивание данных
**Описание риска:** Конфиденциальные данные могут устареть, но это менее критично, чем другие риски.

**Обоснование актуальности:**
- Персональные данные клиентов должны быть актуальными для корректной работы
- Устаревшие данные о собственниках могут привести к ошибкам в начислении ЖКУ
- Риск относительно низкий по сравнению с утечкой или искажением

**Оценка риска:** Незначительный

---

### 2.4. Секретные данные

#### 2.4.1. Утечка данных
**Описание риска:** Утечка криптографических ключей, учётных данных администраторов или данных интеграций может привести к полной компрометации систем.

**Обоснование актуальности:**
- Утечка ключей доступа к партнёрским API может привести к несанкционированному доступу к данным клиентов
- Компрометация учётных данных администраторов может привести к полному контролю над системами
- Утечка данных интеграций с госорганами (СМЭВ) может привести к серьёзным правовым последствиям
- Специалист по ИБ один на всю компанию, что увеличивает риск несвоевременного обнаружения утечек
- Нарушен процесс передачи информации о решениях и изменениях специалисту по ИБ

**Оценка риска:** Критический

#### 2.4.2. Потеря данных
**Описание риска:** Потеря криптографических ключей или конфигураций безопасности может привести к невозможности доступа к системам или данным.

**Обоснование актуальности:**
- Потеря ключей шифрования может привести к невозможности расшифровки данных
- Потеря конфигураций безопасности может привести к необходимости полной перестройки защиты
- Критично для восстановления после инцидентов
- Может привести к длительному простою систем

**Оценка риска:** Критический

#### 2.4.3. Искажение данных
**Описание риска:** Искажение конфигураций безопасности или правил доступа может привести к открытию уязвимостей в системах.

**Обоснование актуальности:**
- Искажение правил firewall может открыть несанкционированный доступ
- Некорректные политики доступа могут привести к утечкам данных
- Искажение конфигураций Active Directory может нарушить аутентификацию
- Критично для безопасности всей инфраструктуры

**Оценка риска:** Критический

#### 2.4.4. Некачественные данные
**Описание риска:** Некачественные конфигурации безопасности могут содержать уязвимости.

**Обоснование актуальности:**
- Некачественные политики безопасности могут содержать пробелы в защите
- Отсутствие единых политик по безопасности при работе с партнёрскими API (как указано в проблемах)
- Может привести к созданию уязвимостей в системах

**Оценка риска:** Критический

#### 2.4.5. Обесценивание данных
**Описание риска:** Секретные данные (ключи, токены) могут устареть при ротации, но это нормальный процесс.

**Обоснование актуальности:**
- Ротация ключей и токенов является стандартной практикой безопасности
- Устаревшие ключи должны быть отозваны
- Риск низкий, так как это управляемый процесс

**Оценка риска:** Незначительный

## 4. Выводы

Наиболее критичные риски связаны с **конфиденциальными** и **секретными** данными:

1. **Конфиденциальные данные** — критичны риски утечки, потери и искажения, что подтверждается уже имеющимися инцидентами (клиенты видят данные других клиентов) и проблемами с партнёрскими API.

2. **Секретные данные** — все риски, кроме обесценивания, имеют критический уровень, что связано с возможностью полной компрометации систем при утечке ключей или конфигураций.

3. **Внутренние данные** — критичен риск некачественных данных, что блокирует развитие ML/AI-направления компании.

4. **Публичные данные** — риски в основном значительные, связанные с бизнес-процессами продаж.

Рекомендуется в первую очередь сосредоточить усилия на защите конфиденциальных и секретных данных, а также на улучшении качества внутренних данных для развития аналитического направления.
