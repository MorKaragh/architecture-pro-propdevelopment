# Требования к функциональности умного дома

## Описание функциональности

#### Интеллектуальный домофон. 

Включает функции классического видеодомофона — открытие по звонку. Также есть возможность распознавать пользователей по биометрии (по лицу) и автоматически открывать дверь, если им разрешён доступ в дом.

#### Интеллектуальный шлагбаум.

Включает функции классического управления шлагбаумом и автоматически открывает доступ, если распознаёт номера автомобилей, которым въезд разрешён.

## Описание данных

В систему добавляются следующие данные

| Данные | Классификация |
| ------ | ------------- |
| Идентификатор домохозяйств | Конфиденциальные | 
| Биометрия пользователей | Конфиденциальные, персональные |
| Автомобильные номера допущенных ТС | Конфиденциальные |
| Credentials для сервисов партнёра | Секретные |
| История использования, логи, телеметрия функциональности | Внутренние |

## Требования к интеграции

### Аутентификация и авторизация

1. **Аутентификация пользователей мобильного приложения:**
   - Собственники должны проходить аутентификацию через существующий сервис `auth-service-1` (Keycloak) перед доступом к функциям умного дома
   - Использование существующей системы аутентификации обеспечивает единообразие и упрощает управление доступом

2. **Аутентификация при интеграции с партнёрскими сервисами:**
   - Для взаимодействия с внешними сервисами партнёра (Интеллектуальный домофон, Интеллектуальный шлагбаум) должна использоваться аутентификация на основе API-ключей или токенов
   - Учётные данные для доступа к партнёрским API должны храниться в защищённом хранилище секретов (HashiCorp Vault)
   - Каждый запрос к партнёрским сервисам должен содержать валидный токен аутентификации

3. **Авторизация:**
   - Доступ к функциям умного дома должен быть ограничен только собственниками, зарегистрированными в системе
   - Собственник может управлять только устройствами, связанными с его домохозяйством
   - Принцип минимальных привилегий: собственник имеет доступ только к своим данным и устройствам

4. **Контроль доступа к данным:**
   - Система должна проверять права доступа перед передачей любых данных партнёрским сервисам
   - Партнёрские сервисы не должны получать доступ к данным других домохозяйств или клиентов

### Интеграционное взаимодействие

1. **Протоколы и форматы:**
   - Взаимодействие с партнёрскими сервисами должно осуществляться по протоколу REST API
   - Использование HTTPS для всех внешних коммуникаций (обязательное шифрование трафика)
   - Формат данных: JSON
   - Версионирование API для обеспечения обратной совместимости

2. **Архитектура интеграции:**
   - Создание отдельного сервиса `smart-home-app` (Kotlin, SpringBoot) для работы с умным домом
   - Сервис выступает в роли прокси между мобильным приложением собственников и партнёрскими сервисами
   - Все запросы от мобильного приложения к партнёрским сервисам проходят через `smart-home-app`
   - Прямое взаимодействие мобильного приложения с партнёрскими сервисами не допускается

3. **Обработка ошибок:**
   - Система должна обрабатывать ошибки партнёрских сервисов и предоставлять понятные сообщения пользователям
   - Реализация механизма повторных попыток (retry) при временных сбоях партнёрских сервисов
   - Логирование всех ошибок для последующего анализа

4. **Мониторинг и контроль:**
   - Все запросы к партнёрским сервисам должны логироваться
   - Мониторинг доступности партнёрских сервисов
   - Контроль объёма передаваемых данных для предотвращения утечек

5. **Ограничение доступа:**
   - Использование межсетевого экрана (firewall) для контроля трафика к партнёрским сервисам
   - Ограничение доступа только к необходимым эндпоинтам партнёрских API
   - Валидация всех входящих и исходящих данных

## Требования к системе

### Хранение данных

1. **База данных:**
   - Использование отдельной базы данных `smart-home-db` (PostgreSQL) для хранения данных умного дома
   - Хранение только необходимых данных: идентификаторы домохозяйств, связи между собственниками и устройствами, история использования
   - Биометрические данные и номера автомобилей не должны храниться в базе данных PropDevelopment (они обрабатываются партнёрскими сервисами)

2. **Шифрование данных:**
   - Шифрование данных на уровне базы данных для конфиденциальных полей
   - Шифрование соединений с базой данных (TLS/SSL)
   - Регулярное резервное копирование базы данных с шифрованием резервных копий

3. **Интеграция с хранилищем данных:**
   - Передача данных в единое хранилище данных (DWH) через механизм CDC (Change Data Capture) для аналитики
   - При передаче в DWH должны применяться процедуры анонимизации персональных данных
   - Передаются только внутренние данные (логи, телеметрия), конфиденциальные данные не передаются

4. **Хранение персональных данных:**
   - Минимизация хранения персональных данных в системе PropDevelopment
   - Биометрические данные обрабатываются только партнёрскими сервисами и не хранятся в системах PropDevelopment
   - Соответствие требованиям 152-ФЗ "О персональных данных"

### Хранение секретов

1. **Использование HashiCorp Vault:**
   - Все секреты (API-ключи, токены доступа к партнёрским сервисам) должны храниться в HashiCorp Vault
   - Прямое хранение секретов в коде, конфигурационных файлах или переменных окружения не допускается

2. **Управление секретами:**
   - Реализация ротации секретов на регулярной основе
   - Контроль доступа к Vault: только авторизованные сервисы могут получать секреты
   - Аудит всех операций доступа к секретам

3. **Изоляция секретов:**
   - Разделение секретов по окружениям (dev, test, prod)
   - Принцип минимальных привилегий при доступе к секретам

### Аудируемость

1. **Логирование:**
   - Логирование всех операций доступа к функциям умного дома
   - Логирование всех запросов к партнёрским сервисам с указанием пользователя, времени, типа операции
   - Логирование всех изменений конфигурации и настроек доступа

2. **Хранение логов:**
   - Централизованное хранение логов для последующего анализа
   - Хранение логов в течение срока, установленного политикой компании и требованиями законодательства
   - Защита логов от несанкционированного доступа и модификации

3. **Аудит доступа:**
   - Регулярный аудит доступа к данным умного дома
   - Проверка соответствия фактического доступа назначенным правам
   - Выявление и расследование подозрительной активности

4. **Отчётность:**
   - Возможность генерации отчётов о доступе к данным и использовании функций умного дома
   - Отчёты для соответствия требованиям аудита безопасности

### Надёжность

1. **Доступность:**
   - Обеспечение доступности сервиса умного дома на уровне не ниже 99.5%
   - Реализация механизмов обработки отказов партнёрских сервисов без полной потери функциональности

2. **Резервное копирование:**
   - Регулярное резервное копирование базы данных `smart-home-db`
   - Тестирование процедур восстановления из резервных копий

3. **Масштабируемость:**
   - Архитектура должна поддерживать горизонтальное масштабирование при росте нагрузки
   - Использование асинхронной обработки для операций, не требующих немедленного ответа

4. **Мониторинг:**
   - Мониторинг производительности и доступности сервиса
   - Настройка алертов при превышении пороговых значений ошибок или времени отклика

### Безопасность

1. **Защита данных при передаче:**
   - Обязательное использование HTTPS (TLS 1.2+) для всех внешних коммуникаций
   - Валидация SSL-сертификатов партнёрских сервисов

2. **Защита от несанкционированного доступа:**
   - Реализация rate limiting для предотвращения злоупотреблений
   - Защита от SQL-инъекций и других типов атак на уровне приложения
   - Регулярное сканирование уязвимостей в зависимостях и их обновление

3. **Контроль доступа к данным:**
   - Строгая валидация прав доступа перед каждой операцией
   - Проверка принадлежности устройства к домохозяйству собственника перед выполнением операций
   - Предотвращение доступа к данным других пользователей (защита от горизонтальной эскалации привилегий)

4. **Соответствие требованиям:**
   - Соответствие требованиям 152-ФЗ "О персональных данных"
   - Соблюдение политик безопасности компании PropDevelopment
   - Учёт требований из чеклиста безопасности при проектировании и реализации

5. **Управление инцидентами:**
   - Процедуры реагирования на инциденты безопасности
   - Возможность быстрого отключения доступа к партнёрским сервисам в случае компрометации
   - Уведомление заинтересованных сторон о выявленных инцидентах

6. **Сетевая безопасность:**
   - Использование межсетевого экрана для контроля трафика к партнёрским сервисам
   - Ограничение сетевого доступа только необходимым эндпоинтам
   - Мониторинг сетевого трафика на предмет аномалий
